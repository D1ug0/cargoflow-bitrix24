# ADR 001: Использование NestJS

## Проблема

Интеграции нужны HTTP-контроллеры, валидация, внедрение зависимостей, фоновые сервисы и
архитектура, которую легко объяснить на собеседовании.

## Решение

Использовать NestJS с TypeScript для API и отдельного контекста воркера.

## Альтернативы

Прямое использование Express/Fastify; интеграция только на PHP; единый неструктурированный
Node.js-процесс.

## Обоснование

Модули, провайдеры, декораторы, валидация DTO и Swagger явно обозначают границы компонентов,
при этом сохраняя низкоуровневый контроль над RabbitMQ и Redis.

## Последствия

Потребуется больше настройки фреймворка и метаданных декораторов; общая бизнес-логика должна
оставаться слабо связанной с фреймворком.
