# ADR 002: Использование RabbitMQ

## Проблема

Вебхуки Битрикс24 должны получать быстрый ответ, хотя внешние вызовы могут завершаться ошибкой
или ограничиваться по частоте.

## Решение

Сохранять событие в outbox и публиковать его в RabbitMQ как устойчивое сообщение. Обрабатывать
сообщения с ручным подтверждением, очередью повторов с TTL, подтверждением публикации и DLQ.

## Альтернативы

Синхронные вызовы; опрос по cron; списки или потоки Redis; Kafka.

## Обоснование

RabbitMQ напрямую поддерживает подтверждения и маршрутизацию недоставленных сообщений, сохраняя
приемлемую для этой нагрузки эксплуатационную сложность.

## Последствия

Появляется ещё один сервис с состоянием; необходимо явно описывать топологию, процедуры повторной
обработки и обеспечивать безопасную обработку дубликатов.
