# 16. Тестирование

Автоматические тесты покрывают контракты, переходы статусов, retry backoff, расчёт маржи и риска.

```bash
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
docker compose config
```

После `docker compose up --build` проверьте:

1. `/api/health` сообщает `up` для всех зависимостей.
2. Seed-машины видны в `/vehicles` и dashboard.
3. Создайте рейс без машины в dashboard, назначьте свободный экипаж и проведите статусы до
   `CLOSED`; машина и водитель должны снова стать доступными.
4. `POST /trips` работает; дубль `bitrixDealId`, неверная дата, повторное назначение и перескок
   стадии дают ожидаемые ошибки.
5. Корректное событие Bitrix24 даёт `accepted`, повтор — `ignored`, неверный токен — 403.
6. Остановите RabbitMQ, примите событие, запустите RabbitMQ и проверьте публикацию outbox.
7. Укажите неверный Bitrix endpoint и проверьте три повтора и DLQ.
8. Передайте корректный UUID в `x-correlation-id` и убедитесь, что API вернул его без изменений.
   Повторите запрос с произвольной строкой: API должен заменить её новым UUID.
9. Найдите один `correlationId` в `/integrations` и логах.

Для реального Bitrix24 используйте учебный портал и синтетические контакты. Полноценные
интеграционные тесты во временных контейнерах остаются следующим этапом.
