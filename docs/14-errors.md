# 14. Обработка ошибок

| Статус | Смысл                     | Пример CargoFlow                           |
| ------ | ------------------------- | ------------------------------------------ |
| 400    | неверный запрос           | некорректный UUID или лишнее DTO-поле      |
| 401    | нет аутентификации        | зарезервировано для production gateway     |
| 403    | доступ запрещён           | неверный токен события Bitrix24            |
| 404    | объект не найден          | нет машины или рейса                       |
| 409    | конфликт состояния        | дубль, занятая машина, запрещённый переход |
| 422    | предметно неверные данные | форма события или дата доставки            |
| 429    | ограничение запросов      | Bitrix24 throttling, worker повторит вызов |
| 500    | внутренняя ошибка         | клиент не получает технические детали      |
| 503    | зависимость недоступна    | Redis, RabbitMQ, Bitrix24 или health check |

Timeout, network error, 429 и 5xx повторяются с backoff и после лимита попадают в DLQ. Ошибки
маппинга тоже остаются в журнале/DLQ, а не повторяются бесконечно. Ищите один `correlationId` в
ответе API, PostgreSQL, свойствах RabbitMQ и логах контейнеров.
